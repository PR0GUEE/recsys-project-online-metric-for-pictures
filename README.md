# Ранжирование постов по пользовательским сигналам

Учебный проект по рекомендательным системам на данных [Qilin](https://huggingface.co/datasets/THUIR/Qilin) — логах поиска постов в китайской соцсети. Проверяем, как меняется выдача при обучении на кликах со штрафами за пропуски и при уточнении пользовательского запроса с помощью LLM.

## Что делаем

Для каждого запроса берём доступные посты с исходных позиций 1–10. Пропуски позиций и короткие выдачи сохраняем. Задача модели — переставить этот набор, поставив более полезные посты выше.

Обучаем две модели с одинаковыми признаками и разными целями:

- **X:** клик по посту даёт 1, отсутствие клика — 0.
- **Y:** клик даёт 1, а некликнутый пост выше другого кликнутого поста получает отрицательный штраф. Сила штрафа зависит от исходной позиции.

Так проверяем, помогает ли дополнительный сигнал от пропусков по сравнению с обучением только на кликах.

Во второй части уточняем запрос перед ранжированием. По эмбеддингу находим похожие исторические запросы из train и передаём их вместе с исходным запросом в LLM. Она предлагает более понятную формулировку, которую используем вместе с оригиналом. Затем та же модель Y переставляет тот же набор постов. Сравниваем её работу с исходным и уточнённым запросами.

Сначала проверим готовую LLM. Дообучение через LoRA рассматриваем как следующий шаг: для него нужно собрать и проверить пары «запрос — уточнение». Готовых эталонных уточнений в Qilin нет.

## Как устроена модель

Одна строка данных — пара «запрос — пост». Готовый [multilingual-e5-small](https://huggingface.co/intfloat/multilingual-e5-small) переводит запрос и текст поста в числовые векторы. Эти векторы, их сходство и простые признаки текста подаём в [CatBoostRegressor](https://catboost.ai/docs/en/concepts/python-reference_catboostregressor). Сам текстовый энкодер не дообучаем.

Каждая модель предсказывает одно число для каждого поста. Сортировка по этому числу даёт новый порядок выдачи. Позиции используем для построения цели Y; клики, лайки и фактическое время просмотра во входные признаки не подаём.

## Данные и оценка

В Qilin используем запросы, тексты постов, позиции показов и пользовательские реакции. Запросы делим по времени на train, validation и test. Все посты одного запроса остаются в одной части выборки.

В первой части сравниваем исходный порядок Qilin и перестановки двух моделей. Во второй фиксируем модель Y и меняем только представление запроса. Банк похожих запросов собираем только из train, без будущих запросов и тестовых реакций.

Лайки оставляем для финальной проверки на test: считаем **LikeNDCG@10** и долю лайков в топ-1, топ-3 и топ-5. Дополнительно проверяем соответствие постов исходному запросу вручную и отмечаем случаи, когда уточнение изменило его смысл. Во всех вариантах набор кандидатов для запроса одинаковый.

## Состояние проекта

Сейчас в репозитории только описание проекта. Поля данных и размеры выборок проверены, обучение моделей ещё не запускали. Код подготовки данных, обучения и оценки, а также инструкции по запуску добавим по мере реализации.
