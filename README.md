# Сравнение плотной и разреженной онлайн метрики при ранжировании картинок

Учебный проект по рекомендательным системам.

Репозиторий: [PR0GUEE/recsys-project-online-metric-for-pictures](https://github.com/PR0GUEE/recsys-project-online-metric-for-pictures).

## Задача

Хотим проверить, как способ построения обучающей метки влияет на порядок картинок в поисковой выдаче. Сравним обычный клик **X** и клик с позиционным штрафом за пропуски **Y**.

На входе — запрос и доступные документы с исходных позиций 1–10 в Qilin. На выходе — новый порядок тех же документов. Пропуски позиций и выдачи короче десяти сохраняем. В Qilin картинка служит обложкой поста, поэтому клик и лайк относятся к посту целиком.

Обучающий сигнал строим из онлайн-логов, а само сравнение проводим офлайн. Основной вопрос: **помогут ли штрафы за некликнутые результаты выше клика поднять более полезные картинки выше?**

## Что именно обучаем

Обучаем два отдельных **CatBoostRegressor**. Одна строка таблицы — пара «запрос — документ», целевая переменная — число X или Y.

Текст запроса и заголовок поста кодируем одним готовым [multilingual-e5-small](https://huggingface.co/intfloat/multilingual-e5-small). Энкодер заморожен, китайские тексты используем в оригинале. Если заголовка нет, берём начало текста поста.

В CatBoost передаём:

- числовой вектор запроса и числовой вектор текста поста;
- косинусное сходство этих векторов;
- длины текстов и тип поста.

Модели получают одинаковые признаки и обучаются с RMSE. Различается только обучающая цель. Исходную позицию, клики, лайки и фактическое время просмотра во входные признаки не включаем. В минимальном варианте пиксели изображений модель не использует; сами картинки нужны для ручной проверки выдачи.

После обучения каждая модель предсказывает число для каждого доступного документа. Сортируем документы по убыванию этого числа и получаем две перестановки: CatBoost-X и CatBoost-Y.

## Две обучающие цели

**X — разреженный сигнал:** клик получает 1, отсутствие клика — 0.

**Y — более плотный сигнал:** клик получает 1. Если документ не кликнули, но ниже него среди доступных кандидатов был клик, назначаем отрицательную метку. Чем выше исходная позиция пропущенного документа, тем сильнее штраф. У остальных документов метка 0.

```text
X_i = c_i
Y_i = c_i - alpha * (1 - c_i) * S_i / log2(1 + p_i)
```

Здесь `c_i` — факт клика, `p_i` — исходная позиция, `S_i = 1`, если среди тех же кандидатов есть клик на более низкой исходной позиции. Силу штрафа `alpha` выбираем на validation по кликам. Пропущенным позициям метки не придумываем.

Условный пример: один клик на позиции 4, `alpha = 1`.

| Позиция | 1 | 2 | 3 | 4 | 5–10 |
| --- | ---: | ---: | ---: | ---: | ---: |
| X | 0 | 0 | 0 | 1 | 0 |
| Y | −1 | −0,63 | −0,50 | 1 | 0 |

Под плотностью понимаем долю ненулевых меток. Строки с нулевой меткой участвуют в обучении обеих моделей.

Опираемся на [Reinforcement Online Learning to Rank with Unbiased Reward Shaping](https://arxiv.org/abs/2201.01534), Zhuang, Qiao, Zuccon, 2022 (ROLTR). Из статьи берём идею отрицательной награды. Пропуски выше клика также рассматриваются в [Joachims et al., 2005](https://www.cs.cornell.edu/people/tj/publications/joachims_etal_05a.pdf). Наша самостоятельная часть — задать позиционный штраф и сравнить две метки в CatBoost на Qilin. Полный RL-алгоритм статьи не воспроизводим; наша формула сама по себе не гарантирует несмещённость.

## Данные

Используем [THUIR/Qilin](https://huggingface.co/datasets/THUIR/Qilin), [статья о датасете](https://arxiv.org/abs/2503.00501).

| Источник | Поля для проекта |
| --- | --- |
| `search_train/search_test` | Текст текущего запроса, ID запроса, пользователя и сессии, список показов |
| `search_result_details_with_idx` внутри search | `note_idx`, исходная позиция, время, клик и лайк |
| `notes`, связь по `note_idx` | Заголовок, текст, тип поста и путь к изображению |

Сохраняем все запросы хотя бы с одним доступным документом на позициях 1–10. Точные дубли объединяем, повтор одного документа оставляем на минимальной исходной позиции. Если разных документов на одной позиции несколько, используем порядок `(position, note_idx)` и ограничиваем список десятью. Отсутствие текста не удаляет документ: используем нулевой вектор и признак отсутствия текста.

В исходном train 44 024 запроса, в официальном test — 6 192. После временного разбиения и сбора кандидатов:

| Часть | Запросы | Пары «запрос — документ» |
| --- | ---: | ---: |
| Train | 27 963 | 213 139 |
| Validation | 6 811 | 50 691 |
| Test | 6 191 | 47 657 |

Запросы с одной картинкой сохраняем. Исключены только 44 запроса без документов в диапазоне 1–10: 41 в train, 2 в validation и 1 в test.

## Разбиение и проверка качества

Делим запросы по времени, целиком вместе с их документами. Времена официальных train/test пересекаются, поэтому train очищаем от более поздних запросов и сессий, встречающихся в test. Для train/validation также убираем сессии через границу. Границы: `t1 = 27.11.2024 16:53:31 UTC`, `t2 = 27.11.2024 19:27:38 UTC`.

На train обучаем модели. На validation выбираем общие настройки и силу штрафа по кликам. Затем фиксируем процедуру и один раз оцениваем test. Лайки не используем ни при обучении, ни при подборе параметров.

Сравниваем три порядка одного и того же набора кандидатов:

1. Исходный порядок Qilin.
2. CatBoost-X, обученный на кликах.
3. CatBoost-Y, обученный на кликах со штрафом.

Для оценки используем относительные места 1…n среди доступных кандидатов во всех трёх вариантах. Исходные номера с пропусками сохраняем для построения Y.

Основная оценка — **LikeNDCG@10**: чем ближе исторически лайкнутые документы к началу, тем лучше. Усредняем по test-запросам, запросу без лайков задаём 0. Отдельно показываем число запросов с лайками и среднее на них.

Также строим распределение лайков: для каждого запроса с лайками считаем их долю в топ-1, топ-3 и топ-5, затем усредняем по запросам. Для разности Y−X покажем 95% доверительный интервал с учётом зависимости запросов одного пользователя.

Ручная проверка: два участника независимо оценят соответствие картинок запросу на 50–100 случайных test-запросах, скрыв названия моделей и реакции. Китайский запрос покажем вместе с переводом.

Исторические реакции зависят от старого показа. Рост офлайн-метрики не доказывает рост реальных лайков после перестановки. A/B-тест в план не входит.
